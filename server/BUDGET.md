# AeroAPI spending gate

The sole provider integration is `flightdeck/connector.py`. Its only paid operation is `GET /flights/{ident}`. It cannot call arbitrary endpoints and does not follow pagination links or redirects.

## Conservative accounting

Prices reviewed on **19 October 2026**:

- Flight-information lookup: published **$0.005 per result set**, capped with `max_pages=1`.
- Account-wide usage lookup: published **$0**.
- This installation reserves **$0.01 per flight-information call**, twice the published price.
- Operational ceiling: **$4.50/month**. The configured budget may be lower, never higher. An additional $0.50 remains below the requested $5 limit.

Before each paid request, the connector queries `/account/usage?all_keys=true` and records the maximum observed undiscounted account cost. An unavailable, malformed, stale or non-finite usage report prevents paid requests. The provider documents account metering as updating every ten minutes.

The gate compares **all local reservations plus the highest reported account usage** with the $4.50 ceiling. This intentionally double-counts our own usage rather than estimating which requests the lagging report includes. It therefore stops earlier than strictly necessary. Integer microdollars and upward rounding are used throughout; floating-point comparisons do not authorize spending.

Reservations are committed with SQLite `BEGIN IMMEDIATE` **before** the HTTP request. Concurrent processes share that ledger. A reservation is never refunded, even for network timeouts, errors, process crashes, cancellations or unknown outcomes. There are no automatic retries. A durable limit of four paid requests per rolling minute allows headroom for the free usage checks within the Personal tier's ten result sets/minute, without assuming free requests are exempt. Forced refresh still shares a 60-second cache.

Within 24 hours of a UTC month boundary, each reservation counts in both adjacent months, conservatively covering timezone/processing ambiguity. Unexpected page counts or response sizes latch a persistent billing block; further paid calls require review. Changing the API key in an existing ledger is blocked rather than resetting spending.

The current price review expires **18 November 2026**. Live calls fail closed after that date. Review the provider’s prices and endpoint semantics before explicitly extending `FLIGHTDECK_PRICING_VALID_UNTIL`; it is not automatically rolled forward.

## What a local gate can guarantee

It enforces a durable, conservative request budget for **this installation at the reviewed prices**. It cannot control charges generated by other applications, other people, provider billing changes, taxes, subscription minimums, or deliberate deletion of the database. Account metering is delayed, so shared-account external usage cannot be perfectly bounded. Use a dedicated Personal account for this app and a provider-side spending cap if available. The $5 free allowance is not treated as spendable credit; all requests count against our limit before any free allowance.

Never delete, reset, edit downward, restore an old copy of, or switch around the usage ledger in order to resume calls. When migrating the service, stop it and back up the entire SQLite database consistently (including WAL state using SQLite's backup API). Do not copy only the main database file while it is running. If the ledger is lost or a billing block appears, disable live mode, reconcile the provider dashboard including pending usage, and establish a conservative baseline before resuming. User trip deletion does not delete billing records.
